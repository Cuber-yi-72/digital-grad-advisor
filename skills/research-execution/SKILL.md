# 执行与诊断 · 改造层（工科导师）

## 必读上游

1. `vendor/phd-skills/debug/SKILL.md`  
   **禁止**「可能是 X，我改一下试试」。顺序不可颠倒：便宜探针 → 标明是假说 → 冒烟检验 → 一次只改一个对照 → 才允许声称原因。
2. 若学生要复现某篇论文的实验：`vendor/phd-skills/reproduce/SKILL.md`（把训练脚本语言改成：样品、仪器方法文件、关键参数是否写全）。

无 vendor：仍执行 probe→假说（标明假说）→今日最小冒烟→才允许声称原因。禁止「可能是 X，改一下试试」。

## 把 ML 探针翻译成实验室探针（Step 1）

在提出任何假说前收集：

- 对照今天做了吗？结果？
- 原始数据路径，还是只剩处理好的图？（不信任口头摘要，让学生打开文件）
- 批次号、试剂/靶材批次、温湿度、操作者、仪器方法文件名，与上次成功批次的差异清单
- 仪器状态：真空、基线、校准日期、是否报错（对应上游的 dmesg / nvidia-smi）
- 记录是否当天写完；无记录按没做

## 假说分类（仍是假说，直到冒烟）

| 类 | 冒烟检验（今天能做的最小实验） |
|----|-------------------------------|
| 设备 | 停手找管理员；用标准样打基线 |
| 测量 | 同一片复测、换夹具/电极、空白样品 |
| 操作 | 与师兄并排操作或录像关键步骤 |
| 设计 | 变量是否一起漂；回到 experiment-design |
| 假设为假 | 对照成立且测量稳定仍无效应 → 这是结果 |
| 测错范围 | 数量级扫描，不加密无效区 |

## 声称原因的门槛（上游 Step 5）

必须引用具体探针输出。证据不够就说「还不知道」，给下一个探针。禁止把曲线调漂亮。

阴性结果：写全条件，能证伪则缩小问题（须导师同意才换题）。

## 周计划

本周一个主问题；三个时间盒；周五前一张图/表；设备黄了的桌面备路（矩阵、脚本、故事线）。

实验记录用 `03-模板/实验记录.md`。中期考核材料用 `03-模板/中期考核.md`（对照开题、失败支线、剩余闸门）。
