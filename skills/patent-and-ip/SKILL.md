# 专利与知识产权

工科组里专利常是毕业杠和转化入口。公开窗口一旦错过，新颖性可能没了。

## 先收集

- 学校是否要求先专利后论文
- 是否企业联合、有无 NDA
- 已公开：组会墙报、预印本、答辩、聊天机器人日志？
- 发明点一句话、谁做了关键贡献

## 工作流

### 1. 时序（默认教条）

```text
实验室内部验证 → 交底书 → 导师+专利所评估
    → 提交申请（或学校流程的登记）
    → 再投论文 / 会议 / 预印本
```

任何**足以实施该方案的公开**都可能毁掉绝对新颖性（各国细则不同，标「待核专利所」）。

提醒：把完整配方、工艺窗口、电路关键参数贴进公共 AI，视为一种公开与泄密风险。只问方法论，或脱敏，或用学校允许的私有环境。

### 2. 这东西像不像专利

更像专利：

- 有技术手段，不是纯科学发现或抽象想法
- 能实施（材料、步骤、结构、参数范围）
- 相对最接近现有技术有可说的效果（成本、寿命、良率、某工况）

更不像：

- 只换了个应用场景的形容词
- 效果全靠不可重复的手艺且写不清
- 已经在自己论文里把实施例写全了

检索：中文专利库 + Google Patents / Espacenet，用结构与功能词，不只用论文关键词。数字导师给检索式，不编造对比专利号。

### 3. 交底书结构（给学生填，不代写权利要求）

1. 名称（技术对象，不要「一种基于 AI 的智能系统」空壳）
2. 背景：现有技术怎么做、在哪失败（最好能指到一篇专利或产品）
3. 要解决的技术问题（一句）
4. 技术方案：结构/步骤/参数范围（实施例 ≥ 1 个可实施）
5. 有益效果：与对照比，能写清测试条件
6. 替代实施例（防绕开的变体）
7. 附图及简要说明
8. 发明人贡献说明（防署名争议）

权利要求由专利代理写。数字导师只帮学生把技术交待清楚，并指出「写得太窄只保护一个温度」或「写得太宽无法实施」。

### 4. 与论文的分工

- 专利：保护实施方案与变体，语言要覆盖范围
- 论文：讲机制、证据、局限；实施例不要在申请前提交

同一批数据可以支撑两者，但公开顺序听导师与产学研办公室。

### 5. 署名与学校职务发明

学生在组内设备与课题下做的，通常是职务发明。不承诺「你一定是第一发明人」。列贡献事实，让导师定序。

## 输出

- 公开风险评估
- 像/不像专利的判断 + 待核事项
- 交底书提纲与学生需补的实验
- 论文冻结清单（申请前不能发出去的图）

## 红线

- 不做专利代理人，不保证授权。
- 不把未公开技术细节写进可能被用于训练的对话——能概括就概括。
- 不教规避学校知识产权流程。
